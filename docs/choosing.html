A decision guide · August 2026

What should you publish on, and what should serve it?

Two questions people ask in the wrong order. Start with the protocol your readers will use: the server follows from it, and not the other way round.

One · Which protocol should carry your writing?

You do not have to pick only one. But start with the one that matches who you want to reach, and add others later when you have a reason.

  • Who do you want to be able to read this, without installing anything first?
    • Anyone at all: I will put this address on a CV or in an email The web, mirrored and keep a Gemini copy from the same folder
    • Software, mostly: AI agents, scripts, things that index The web, plus /llms.txt one fetch instead of a crawl; Markdown by suffix
    • People who chose to be in a quieter place
      • Is it a site or blog: several pages, updated over time?
        • Yes, and I want feeds, replies and an audience that is growing Gemini the living smolnet, and the best clients
        • Yes, but I want it readable in thirty years by software nobody maintains Gopher unchanged since 1991, a separate community
        • Yes, but I object to mandatory encryption for public documents Spartan gemtext, no TLS ceremony
      • Or is it one short thing: a status, a note, what you are up to?
        • A status about me, answerable in one command Finger a “now” page with no page
        • A single message, and I like the smallest possible thing Nex send a path, get bytes, done

One server, seven doors

This is the same machine, the same hostname, the same folder of writing. Only the scheme at the front of the address changes, and with it the port, the client, and what the protocol is actually good at. Read down the seven and the differences stop being abstract.

One folder produced all seven. Nothing above was written twice, and turning any of them off is a single line of configuration.

Two · Which server should run it?

Five good servers, all different. What separates them is not how they serve files: it is everything else they will or will not do.

  • Do you need the server to run code: CGI, FastCGI, scripts, dynamic pages?
    • Yes: I want to program my capsule
      • In Python, with an extension ecosystem GmCapsule
      • With CGI or SCGI, plus certificate zones Molly Brown
      • With FastCGI or a reverse proxy, many hostnames, ACME gmid
    • No: static documents are the point
      • I want more than Gemini: the web, or Gopher, Spartan, Nex, Finger usv the only one that does
      • I want AI agents to read it cleanly, and some of them to write to it usv llms.txt and Markdown by default; writes scoped by capability
      • Gemini only, then. Do readers or agents need to write to it, over Titan?
        • Yes, with certificate-gated zones and a config file I can read usv
        • Yes, and I want the reference implementation GmCapsule
        • No: I want the smallest, most settled thing that works Agate static by policy, and proud of it

What usv took from the others

Arriving last is only an advantage if you read the others first. Each of these is a decision usv did not have to make for itself, and the project that made it.

From Agate

Certificates that never regenerate

Auto-minted per hostname, expiring far enough out to be irrelevant, and never silently reissued, because under trust-on-first-use a new key looks exactly like an attacker. usv adopted this design almost wholesale.

From gmid

Take privilege seriously

gmid separates privileges across processes. usv stayed single-process but moved the lesson into its systemd unit: an empty capability set, no new privileges, a read-only root, and so no privileged ports, which is why Gopher defaults to 7070 rather than 70.

From Molly Brown

Authorisation belongs to a path

Certificate zones scoped by path prefix, with the 6x status family doing the talking. usv’s zones, and its rule that a gated path never reaches a cleartext protocol: grow from this.

From GmCapsule

The reference is the spec in practice

usv checked its Titan behaviour against the reference implementation rather than the prose alone: the fastest way to discover your reading of a specification is not the one everyone else implemented.

From the wider smolnet

Match what is served, not what is written

Gopher’s conventions came from Floodgap’s living gopherspace. Spartan taught a smaller lesson with teeth: its server answers a bare content type, so usv stopped sending a redundant charset that gave strict clients something to disagree with.

Being the newest is not a feature. usv arrived in August 2026, after the other four, which is why it could learn from them, and equally why it has had the least time to be proven wrong. Agate, gmid, Molly Brown and GmCapsule have each run real capsules for years.

If you need a static Gemini server and nothing more, the settled choice is the better engineering decision. Choose usv for what it reaches: several protocols and two audiences from one folder, not because it is recent.
