Pick one

Six colour schemes, all built on Ember Oxide

Every one uses the same eight tokens, so choosing is a matter of taste rather than of rework: swapping the scheme is swapping eight values. This page is itself wearing Ember, so you are already looking at one of them at full size.

All six are contrast-checked.

Measured, not estimated. Body text clears 10.8:1 against its ground in the worst scheme and code text clears 5.4:1, against the 4.5:1 that normal text needs. That is why the amber in the two light schemes is burnt down rather than pure: pure Ember Oxide manages only about 2.9:1 on paper white. The chips in those two schemes sit on a darker ground again, because small bold type needs the full ratio and pure ember gave it 4.1:1.

The eight tokens

A scheme is only ever these. Anything a page needs beyond them is a mistake in the page, not a gap in the scheme.

TokenDoes
--paperThe page ground
--cardAnything raised off it: panels, notes, code blocks
--railBorders and rules
--softSecondary text: ledes, captions, dimmed detail
--inkBody text
--code-bgThe ground behind code
--code-inkCode text and links
--emberThe brand mark: chips, accents, focus, the left rail on a card

Keeping the old-school in it

Devices that read as terminal and gopher without becoming a costume. Each is live below, not a description of one. All of them are plain text and CSS: nothing here needs a script, which matters for a project that refuses to ship any.

Box-drawing frames

Rules and panels made of ─ │ ┌ ┐ └ ┘ rather than CSS borders. Costs nothing, survives copy-paste, and is the same character set a gophermap uses.

┌──────────────────────────────────┐ │ usv status │ │ │ │ hosts ............ 1 │ │ gemini ........... 0.0.0.0:1965 │ │ gopher ........... off │ │ published ........ 12 pages │ └──────────────────────────────────┘

A gophermap, shown as one

Item-type prefix, display string, selector. Colouring the type character teaches the format at a glance, and it is the one piece of gopher a newcomer actually has to understand.

iWelcome to the gopherhole i 1Phlog /phlog 0About this hole /about.txt hAlso on Gemini URL:gemini://… .

Gemtext link lines, left as they are

A => at the head of a link is how the format actually looks. Keeping it in the rendered page is a small act of honesty about where the words come from.

=> /smolnets.html The five networks => /agents.html Agents, read and write => gopher://… The same, over gopher

A prompt and a live cursor

One blinking block after a command is enough to say "terminal" without a full skin. It stops blinking for anyone who has asked for reduced motion.

A repeating gradient and a text-shadow. Decorative only: it sits on a wrapper, never on text a reader must follow, so nothing is harder to read than it was.

Text controls

Where a page needs something that looks actionable, bracket it rather than build a button. It reads correctly in a text browser and degrades to exactly itself.

Protocols: [ gemini ] [ gopher ] [ + add ]

An honest measure

The old networks wrap at 70-80 columns because terminals did. Holding prose to the same measure is why these pages are readable, and it costs one max-width.

Seventy columns is about this wide, which is also how wide a gophermap display string can be before clients start truncating it.
The one to be careful with.

Scanlines and bloom are the devices most likely to age badly and the most likely to hurt someone. Used on a masthead or a specimen block they are charm; used behind body text they are a legibility bug. The rule worth keeping: decoration goes on things nobody has to read.

A recommendation, since you asked for one

Ember as the default and Foolscap as its light twin, they are the same scheme at two ends, so a reader's system preference picks between them and nothing has to be chosen twice. Phosphor is the one worth shipping as an option rather than a default: it is the most distinctive thing here and the least comfortable to read for long. Burrow is the best answer to "make it feel like gopher" if the default should carry that on its own.
